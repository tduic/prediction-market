# Phase 1 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the three worthwhile pieces of the fork branch
`sandsthebrand/phase1-arb-hardening` into `main`, fixing the defects the
review found: (A) a fee-aware profitability gate, (B) a persistent execution
halt plus order-book depth sizing, (C) a Polymarket CLOB V2 execution client.

**Architecture:** Pure fee math lives in `core/engine/fees.py`. Network reads
(fee metadata and executable depth, both from public endpoints) sit behind a
`MarketData` provider in `execution/market_data.py`. `ArbitrageEngine` gets it
from a module-level accessor, so tests swap in a zero-fee, unlimited-depth
stub through one autouse fixture. The halt is a single-row table checked
before every order and tripped on unknown or unbalanced fills. The V2 client
replaces the archived `py-clob-client` path in live mode.

**Tech Stack:** Python 3.12, aiosqlite, httpx, pytest-asyncio (auto mode),
`py-clob-client-v2==1.2.0`.

**Spec:** this plan plus the fork review in `handoff.md`. Verified API facts
(probed 2026-09-27):
- Polymarket `GET https://clob.polymarket.com/clob-markets/{condition_id}`
  (public) returns `fd: {"r": rate, "e": exponent, "to": taker_only}` or
  `fd: null` (= fee-free, matching the SDK's `rate=0` default). Observed
  `r` values: 0, 0.03, 0.05, all with `e=1`. Fee = `C * r * (p(1-p))^e`
  (SDK `fees.py`).
- Polymarket `GET /book?token_id=` (public): `asks`/`bids` lists of
  `{"price": str, "size": str}`. Asks are ordered worst-first, so depth
  must be summed by price, not by position.
- Kalshi `GET {base}/markets/{ticker}/orderbook` (public):
  `{"orderbook_fp": {"yes_dollars": [[price, qty], ...], "no_dollars": [...]}}`
  where both are bid lists. BUY YES at <= p consumes NO bids with price
  >= 1-p; SELL YES at >= p consumes YES bids with price >= p.
- Kalshi fee metadata: `/markets/{t}` -> `event_ticker`; `/events/{e}` ->
  `series_ticker`, optional `fee_type_override`/`fee_multiplier_override`;
  `/series/{s}` -> `fee_type` (`quadratic`), `fee_multiplier`. Taker fee =
  `ceil_to_cent(0.07 * multiplier * C * P * (1-P))`.
- Internal IDs: Polymarket `poly_<condition_id>`, Kalshi `kal_<ticker>`. The
  exchange identifier is `markets.platform_id`. Never send the internal ID.

## Part A: Fee-aware profitability gate

### Task A1: Pure fee math (`core/engine/fees.py`)
**Files:** Create `core/engine/fees.py`, `tests/unit/test_fees.py`.

**Produces:**
```python
@dataclass(frozen=True)
class FeeParams:
    platform: str          # "polymarket" | "kalshi"
    rate: float            # effective coefficient (Kalshi: 0.07*multiplier)
    exponent: float = 1.0  # applied to p*(1-p)
    decimals: int = 2      # upward rounding precision (Kalshi 2, Polymarket 5)

def taker_fee(params: FeeParams, quantity: float, price: float) -> float
def kalshi_params(multiplier: float = 1.0, base_rate: float = 0.07) -> FeeParams
def polymarket_params(rate: float, exponent: float) -> FeeParams   # decimals=5

@dataclass(frozen=True)
class ArbEconomics:
    quantity: float; buy_price: float; sell_price: float
    gross: float; buy_fee: float; sell_fee: float; net: float
    net_edge_per_contract: float

def arb_economics(buy_price, sell_price, quantity, buy_fees: FeeParams,
                  sell_fees: FeeParams) -> ArbEconomics | None
def unit_net_edge(buy_price, sell_price, buy_fees: FeeParams,
                  sell_fees: FeeParams) -> float   # unrounded, per contract
```
- `taker_fee`: `ceil(q*r*(p(1-p))**e * 10**d) / 10**d`. Use a
  `round(x, 9)` guard before `ceil` so float noise (0.0700000001) doesn't
  bump a whole cent. Validate 0<p<1, q>0, r>=0, 0<=e<=8, else `ValueError`.
  Exponent 0 is legal and must stay 0 (fork bug: `e or 1.0`).
- The sell leg's fee uses `sell_price`, which is symmetric in p(1-p), so it
  is right both for a Kalshi sell and for a translated Polymarket BUY NO at 1-p.
- `arb_economics` returns None on invalid input. gross = (sell-buy)*q.
- Tests: Kalshi 100 @ 0.50 -> 1.75. Kalshi 1 @ 0.50 -> 0.02 (0.0175
  rounds up). Kalshi 10 @ 0.10 with multiplier 0.5 -> 0.04. Polymarket
  rate 0.05, e=1, 10 @ 0.40 -> 0.12. Polymarket rate 0 -> 0. Exponent 0
  -> `q*r`. Float-noise guard (0.07*100*0.5*0.5 must be exactly 1.75, not
  1.76). Invalid inputs raise or return None. An arb whose gross edge is
  eaten by fees has net < 0.

### Task A2: Fee discovery (`execution/market_data.py`)
**Files:** Create `execution/market_data.py`, `tests/unit/test_market_data_fees.py`.
Modify `tests/conftest.py` (autouse stub).

**Produces:**
```python
class MarketData(Protocol):
    async def fee_params(self, db, market_id: str) -> FeeParams | None
    async def executable_depth(self, db, leg: OrderLeg) -> float | None  # Task B3

class LiveMarketData:  # httpx.AsyncClient, TTL cache (default 3600s)
    def __init__(self, http: httpx.AsyncClient | None = None,
                 poly_host="https://clob.polymarket.com",
                 kalshi_base=<KALSHI_API_BASE or elections default>,
                 ttl_s=3600.0)
class StaticMarketData:  # tests / explicit: fixed params, fixed depth
    def __init__(self, fees: dict[str, FeeParams] | None = None,
                 depth: float | None = float("inf"))

def get_market_data() -> MarketData      # lazily builds LiveMarketData
def set_market_data(md: MarketData | None) -> None
```
- `fee_params` looks up `platform, platform_id` from `markets` by id. Polymarket:
  `fd` null -> `polymarket_params(0, 1)`. Otherwise `(r, e)` taken as-is.
  Kalshi: market -> event -> series. `fee_type` must be `quadratic` or
  `quadratic_with_maker_fees` (taker side), else None. A missing multiplier
  also gives None. Any HTTP or parse error: log it and return None (fail closed).
- Autouse fixture in `tests/conftest.py`:
  `set_market_data(StaticMarketData())`, whose default fees are zero-rate
  for both platforms. Reset afterwards.
- Tests use `httpx.MockTransport` covering: Polymarket fd present, fd null,
  and HTTP 500 (None). Kalshi series multiplier, an event override that
  beats the series value, an unsupported fee type (None), and a missing
  market row (None). Also that the cache avoids a second fetch.

  applied only at the final size. If unit <= 0, skip
  (`_skipped_unprofitable`).

  `net <= max(0, arb_min_net_profit)` (strictly positive required), skip.

  `fee_estimate_a=buy_fee`, `fee_estimate_b=sell_fee`, replacing the flat
  0.02. `predicted_pnl` in `trade_outcomes` becomes `econ.net`.
- `stats()` gains `skipped_fee_unknown` and `skipped_unprofitable`.
- Tests (StaticMarketData with real params): a spread of 0.03 at mid prices
  with Kalshi 0.07 is rejected. A spread of 0.10 passes and records fee

## Part B: Persistent halt + depth sizing

### Task B1: Halt state (`core/engine/execution_control.py`, migration 019)
**Files:** Create `core/storage/migrations/019_execution_halt.sql`,
`core/engine/execution_control.py`, `scripts/clear_halt.py`,
`tests/integration/test_execution_control.py`.

**Produces:**
```python
async def is_halted(db) -> bool
async def get_halt(db) -> dict | None   # {"reason","halted_at"} when halted
async def halt(db, reason: str, component: str) -> None
async def clear_halt(db, reason: str) -> None
```
- The migration is a single-row table (`id=1 CHECK`). Every statement goes
  on one line where the runner cares, meaning no multi-line `ALTER`. (That
  was fork bug 020. This migration has no ALTER at all.)
- `halt` is idempotent. It keeps the first reason, writes a
  `system_events` row `EXECUTION_HALTED` (critical), and sends a CRITICAL
  alert via `get_alert_manager().send_nowait`. `clear_halt` writes
  `EXECUTION_HALT_CLEARED`.
- `scripts/clear_halt.py --reason "..."`: prints the current halt, clears
  it, and refuses without `--reason`.
- If the table is missing (DB not yet migrated), `is_halted` returns False
  and logs an error.

### Task B2: Enforce halt, stop retrying unknown fills (money path, needs review)
**Files:** Modify `core/engine/arb_engine.py`, `core/strategies/single_platform.py`.
Tests: `tests/integration/test_arb_halt.py`, extend `test_single_platform.py`.
- Check `is_halted` before any order in `_execute_arb_trade` and in the
  single-platform order path. If halted, skip (`_skipped_halted` stat).
- `_submit_with_retry`: `status == "pending"` returns immediately, with no
  retry. The fill is unknown, so a retry could double the position.
- After both legs:
  - either leg `pending`: halt with reason
    `unknown_fill pair=... order=...` and best-effort `cancel_order` on
    that order id.
  - exactly one leg filled (`buy_filled != sell_filled`): halt with reason
    `unbalanced_arb pair=...`.
  - The existing breaker bookkeeping is unchanged.
- Single-platform: a `pending` result halts too, since that position is unknown.
- `/api/system-health`: when halted, add issue `execution_halted` (the
  word "critical" isn't needed; add it to the status rule so a halt means
  `critical`).
- Tests: a pending leg means halted and no retry calls. Unbalanced means
  halted. A halted engine places no orders. Health reports critical.

### Task B3: Executable depth
**Files:** Modify `execution/market_data.py` (`executable_depth`). Test:
`tests/unit/test_market_data_depth.py`.
- Polymarket: resolve via `BookResolver` (including the NO-book
  translation), then GET `/book?token_id=`. BUY sums `asks` with
  price <= limit. SELL sums `bids` with price >= limit.
- Kalshi: ticker from `platform_id`. BUY YES at <= p sums `no_dollars`
  qty where price >= 1-p (1e-9 tolerance). SELL YES at >= p sums
  `yes_dollars` where price >= p.
- Errors or an unknown platform give None. No caching (depth is volatile).
- Tests use MockTransport with the probed payload shapes, including
  worst-first asks.

### Task B4: Depth-capped sizing in the engine (money path, needs review)
**Files:** Modify `core/engine/arb_engine.py`, `core/config.py`
(`arb_min_fill_size`, env `ARB_MIN_FILL_SIZE`, default 1.0). Test:
`tests/integration/test_arb_depth.py`.
- After Kelly sizing and before the net-profit check:
  `size = min(size, depth_buy, depth_sell)`, rounded down to 0.1 (Kalshi
  sizes are cast with `int()`, so also floor Kalshi-leg sizes to whole
  contracts: `size = floor(size)` when either leg is Kalshi). If a depth is
  None: `_skipped_depth_unknown`. If size < `arb_min_fill_size`:
  `_skipped_thin_book`.
- Exposure stays as main computes it (`size*buy + size*(1-sell)`), which
  is correct. Don't port the fork's `size*sell_price`.
- Tests: depth caps the size, None depth skips, and a thin book skips.

## Part C: Polymarket CLOB V2 client

### Task C1: `PolymarketExecutionClientV2` (money path, needs review)
**Files:** Create `execution/clients/polymarket_v2.py`,
`tests/integration/test_polymarket_v2.py`. Modify `requirements.txt`
(add `py-clob-client-v2==1.2.0`, keep legacy until C2).
- Constructor mirrors the legacy client. Signature type defaults to env
  `POLYMARKET_SIGNATURE_TYPE`, default `"1"` as in legacy.
- `_ensure_client`: `ClobClient(host, chain_id, key, creds?, signature_type,
  funder)`. Derive creds if not supplied. Install the SOCKS5 proxy by
  swapping `py_clob_client_v2.http_helpers.helpers._http_client` (same
  pattern as legacy).
- `submit_order`: resolve via BookResolver, `get_tick_size`,
  `create_and_post_order(OrderArgs..., PartialCreateOrderOptions(tick_size),
  OrderType.FAK)` for LIMIT and `FOK` for MARKET. Rejected responses
  (`success` false or no id) mean `failed`. An exception **before** post
  means `failed`. An exception **after** post returned an id (or while
  polling) means `pending` (unknown), never `failed` with zero fill.
- `_poll`: terminal statuses. Matched size > 0 gives filled or partial,
  with price = order price, and the economic price translated back
  (`1-p`) when the leg was translated to the NO book. The fee uses
  `taker_fee(polymarket_params(r, e))` from `get_clob_market_info(condition_id)`,
  where condition_id comes from `markets.platform_id`. An unverifiable fee
  keeps the fill and records `fee_paid=None` plus the error text. On
  timeout: cancel, re-fetch once, and use the matched size if known,
  otherwise `pending`.
- `cancel_order`, `get_order_status`, `get_balance` (collateral /
  `POLYMARKET_BALANCE_SCALE`), `close`.
- Tests inject a fake SDK client (`client._client = Fake(...)`,
  `client._initialized = True`) covering: a full fill, a partial fill, a
  translated NO fill giving economic price 1-p, a rejection giving
  `failed`, a post-then-poll exception giving `pending`, a timeout with a
  late fill giving the partial result, an exponent 0 fee, and the
  condition-id lookup (not the `poly_` id). Proxy install is verified by
  monkeypatching the helpers module.
